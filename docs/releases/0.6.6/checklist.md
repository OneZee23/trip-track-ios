## 1. Бэкенд — сначала он

Клиент 0.6.6 ходит в `POST /journeys/upsert|list|delete` и ждёт секцию
`journeys` в `/sync/pull`. Старый сервер вернёт 404 на новые маршруты и просто
не отдаст секцию — приложение это переживёт, но путешествие не доедет до
второго телефона. Деплой до сабмита — чтобы фича работала с первого дня.

- [ ] Два коммита (`0630c40` модуль + миграция, `c26ad58` «отсутствующий ключ
      не сбрасывает поле») **запушить в `master`** — CI собирает и выкатывает
      только с него.
- [ ] В выкатке едет миграция `AddJourneys`: таблица `journey` с FK на
      `account(id)` ON DELETE CASCADE и индексом `idx_journey_account`.
      Идемпотентна — `CREATE TABLE IF NOT EXISTS`.
- [ ] Проверка живого маршрута (любой свой аккаунт, путешествий может не быть):
      ```
      curl -s -X POST -H "Authorization: Bearer $TOKEN" \
        -H 'Content-Type: application/json' -d '{}' \
        https://api.trip-track.app/journeys/list | jq
      ```
      Ждём `{"journeys": []}` — не 404 и не 500.
- [ ] Проверка синка: `POST /sync/pull` с `entityTypes: ["journey"]` отдаёт
      `journeys: {upserted: [], deleted: []}`. Без правки whitelist в
      `sync-pull.dto.ts` этот запрос падал бы на валидации — она в коммите.

## 2. iOS — пальцем на телефоне

Автотесты закрывают правила; ниже то, что видит только человек.

- [ ] **Создание с экрана поездки.** «…» → «Объединить в путешествие»: в листе
      соседи ±7 дней, все отмечены, галочки снимаются. «Создать путешествие» →
      тост «Путешествие создано».
- [ ] **Мультивыбор.** В «Моих» долгое нажатие на карточку → режим выбора,
      панель внизу ВМЕСТО таб-бара, «В путешествие (N)» открывает тот же лист.
- [ ] **Экран путешествия.** Карта-склейка всех плеч с кружками отметок; четыре
      плитки итога; дни с плечами; стоянка «Тбилиси · 5 поездок по городу»
      раскрывается по нажатию.
- [ ] **Правка дат с пересечением** даёт красную ошибку `journeyOverlaps`, а не
      молчаливый отказ и не второе путешествие поверх первого.
- [ ] **Удаление путешествия оставляет поездки**: подтверждение → в «Моих» на
      месте карточки снова стоят все плечи.
- [ ] **Второй телефон.** С Cloud Sync путешествие приезжает целиком (имя,
      окно дат, исключённые поездки); правка на первом телефоне, ещё не
      уехавшая, не затирается входящим pull.
- [ ] **`LocalDataWipe` и удаление аккаунта** стирают `JourneyEntity` — у неё
      нет связи с поездкой, каскад её не заберёт.
- [ ] **«Это твой дом?»** показывается ОДИН раз; «Нет» гасит подсказки навсегда.
- [ ] **Джанхот туда-обратно в один день** подсказку НЕ вызывает: путешествие
      делает ночь не дома, а не 200 км.
- [ ] **Прогнать `JourneySuggester` по своей базе: после Джанхота (6 сен)
      подсказки нет; после Тбилиси — есть.**

## Известные мелочи, не блокеры

Собрано из ledger'а версии (`.superpowers/sdd/2026-09-09-journeys-066/progress.md`,
строки `minor (deferred)`). Ни одна не меняет поведения на глазах у человека.

- **Заголовок путешествия собирается в трёх местах** (экран, карточка, лист) —
  просится общий `JourneyTitle`; правило заголовка поездки скопировано в лист
  объединения третий раз.
- **Полилинии декодируются мимо `NSCache`** в `JourneyAggregate.start/endCoordinate`
  и в герое экрана — на длинном путешествии это лишняя работа при каждом входе.
- **Чтение базы крупными кусками**: `trips(in:)` и `journeyContaining` читают
  весь список ради одного элемента; `reload()` на любую мутацию дёргает
  `fetchAllTrips()`; лента дней — eager `VStack` вместо `LazyVStack`.
- **`HistoryFolding.fold` не защищён от пересекающихся путешествий с сервера** —
  локально пересечение невозможно (проверка при создании и правке), и вся
  защита в списке — одно `!taken.contains`.
- **Вёрстка**: панель выбора без `maxWidth 380` шире таб-бара на 430-pt
  телефонах; третья копия обхода safe-area; километры кандидата через
  `Int(distance/1000)` — без группировки разрядов.
- **VoiceOver в режиме выбора**: у галочки нет подписи, карточка всё ещё
  читается как «открыть».
- **Переводы `journeyLegsLabel`/`journeyDrivingLabel`** (IT «Tratte»,
  PT «Trechos») проверены чтением, не носителем.
- **Не покрыто тестом**: поездка без точек и без полилинии; `dateRange`;
  «по последнему или по первому плечу» встаёт карточка в списке.
- **Решения владельца, не баги**: `legCount` не считает местные поездки;
  опорная поездка стоит в листе первой, ломая хронологию; `clearSelection`
  возвращает таб-бар за закрывающимся листом.
- **Бэкенд**: `SyncModule` импортирует `JourneysModule` ради одного
  статического `serialize`; неиспользуемый logger в `JourneysService` — как у
  `vehicles`.
