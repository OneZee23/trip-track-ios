# 0.8.0 «Плюс» — что нажать

**Монетизация отложена (решение владельца, 21 сен 2026).** Подписка «Плюс»,
донат и вписанная вручную поездка спрятаны кюлл-свитчем
`PlusAvailability.isEnabled = false` в
`TripTrack/Services/Plus/PlusAvailability.swift` — их не видит никто ни в
одном регионе, код остаётся в сборке и включится в 0.8.1 или позже. Отсюда
следует:

- Шаги **§1 и §2 (App Store Connect: товары, подписка, App Store Server
  Notifications) для сабмита 0.8.0 НЕ НУЖНЫ.** В разделе In-App Purchase
  при отправке билда выбирать нечего — товары не заводятся вовсе. Разделы
  ниже оставлены как были, только помечены **[ОТЛОЖЕНО НА 0.8.1]** — это
  подготовленный план на момент включения фичи, а не текущий чек-лист.
- Серверная переменная **`APPLE_ALLOW_SANDBOX_NOTIFICATIONS` (она же
  `APPLE_ACCEPT_SANDBOX` в §3 ниже) можно сразу вернуть в `false`** на
  проде, если её включали на время разработки — уведомления от Apple по
  подписке сейчас никому не нужны.
- Остальной релиз (скорость и стабильность, фиксы «Атласа», экспорт GPX/CSV,
  подсказки «Мест») монетизации не касается и сабмитится обычным порядком.

Код на ветках, спека `docs/superpowers/specs/2026-09-19-080-plus-design.md`.

## 1. App Store Connect — товары, ДО билда [ОТЛОЖЕНО НА 0.8.1]

**Не нужно для сабмита 0.8.0** — товары IAP не заводятся, раздел ниже
остаётся планом на момент включения кюлл-свитча.

Apple привязывает In-App Purchase к отправленной сборке на ревью; товар,
заведённый после отправки билда, не попадёт под ревью вместе с ним.

- [ ] **Группа подписок `plus`.** Monetization → Subscriptions → New
      Subscription Group → `plus`. Внутри — два продукта в ОДНОЙ группе (так
      Apple сама разруливает переход между тарифами и не даёт купить оба
      сразу):
      - `com.onezee.TripTrack.plus.yearly` — 1 год, €29,99, Introductory
        Offer → Free → 1 week → «New subscribers».
      - `com.onezee.TripTrack.plus.monthly` — 1 месяц, €6,99, без пробного
        периода.
      Обоим — Display Name, Description, Review Screenshot, локализованная
      цена на всех витринах (Apple пересчитает по базовой €).
- [ ] **Три доната (consumable).** `tip.small` €0,99 (уже есть с прошлых
      версий), `tip.medium` €2,99, `tip.large` €9,99 — новые. Текст обещает
      только «спасибо» и ничего больше (3.1.1: платный функционал без
      раскрытия — частая причина отказа).
- [ ] **Все пять товаров — «Ready to Submit» или «Approved» ДО архивации
      билда.** Пустой список товаров при ревью — типовая причина отказа 2.1
      («guideline 2.1 In-App Purchase products not submitted»).
- [ ] **Family Sharing ВЫКЛЮЧЕН у обоих тарифов.** Локальный
      `Config/TripTrack.storekit` ставит `familyShareable: false`, но
      источник правды для прода — App Store Connect, и расхождение клиент не
      поймает: `PlusStore` принимает право независимо от `ownershipType`, то
      есть включённый в ASC семейный доступ молча раздал бы «Плюс» пятерым.
      Либо выключить, либо завести это решением и снять проверку отсюда.
- [ ] **Paid Apps Agreement активен.** Решение владельца — кодом не
      проверяем, но без него StoreKit не отдаёт товары вовсе, и это ловится
      ТОЛЬКО на устройстве или в песочнице, не тестами.

## 2. App Store Server Notifications и ключ [ОТЛОЖЕНО НА 0.8.1]

**Не нужно для сабмита 0.8.0** — без активной подписки уведомлениям Apple
неоткуда взяться; раздел остаётся планом на момент включения кюлл-свитча.

- [ ] **App Store Connect → App → General → App Store Server Notifications
      → Version 2** (не v1). Оба URL — **одинаковые**, окружение приезжает в
      самом уведомлении:
      - Production Server URL: `https://api.trip-track.app/plus/apple`
      - Sandbox Server URL: `https://api.trip-track.app/plus/apple`
- [ ] **Кнопка «Request a Test Notification»** — придёт `TEST`, сервер
      отвечает 200 и пишет строку в `plus_event` с `outcome = 'test'`
      (отдельная ветка на стороне бэкенда — не `ignored:*`: тестовое
      уведомление обязано отличаться в таблице от настоящего, которое мы не
      поняли). Смотреть лог/таблицу сразу после нажатия.
- [ ] **И убедиться, что уведомление доехало ДО ORIGIN, а не умерло по
      дороге.** Проверка — та же кнопка, но вопрос другой: не «ответили ли
      мы 200», а `SELECT created_at, notification_type, outcome FROM
      plus_event ORDER BY created_at DESC LIMIT 5` — строка с
      `outcome = 'test'` обязана появиться. Цена молчания несимметрична:
      Apple повторяет доставку трое суток и сдаётся, а потерянные `REFUND`/`REVOKE`/`EXPIRED` означают, что
      человек вернул деньги, а «Плюс» остался у него навсегда — `attach` с
      телефона строку не отзывает, `revokedAt` приходит только уведомлением.
      Заметить это потом нечем: пустой `plus_event` выглядит одинаково и в
      норме, и при полной потере доставки. В первую неделю после релиза —
      `SELECT count(*) FROM plus_event WHERE created_at > now() - interval
      '1 day'`.
- [ ] **Cloudflare: `api.trip-track.app` сегодня DNS-only** (в ответе нет
      `cf-ray`), поэтому правила не нужны — как `/s/*` и `/j/*` на сайте, но
      с обратным знаком. Если хост когда-нибудь уйдёт под оранжевое облако
      (лечение RU-DPI шло именно так), `/plus/apple` обязан получить правило
      Bot Fight Mode → skip и никакого челленджа: Apple начнёт получать 403 и
      замолчит навсегда. Подробности — в `docs/plus.md` бэкенд-репозитория.
- [ ] **Ключ App Store Server API — по необходимости.** Нужен ТОЛЬКО для
      запасного пути `POST /plus/attach {transactionId}` (без него обычный
      путь через подписанную транзакцию StoreKit 2 работает целиком). Если
      заводится — Users and Access → Integrations → In-App Purchase → «+»,
      скачать `.p8` (Apple даёт один раз), записать Issuer ID и Key ID.

## 3. Переменные окружения прода (`.env`) [ОТЛОЖЕНО НА 0.8.1]

**Не нужно для сабмита 0.8.0.** Ключевое для этого релиза: серверная
переменная **`APPLE_ALLOW_SANDBOX_NOTIFICATIONS`** (она же
`APPLE_ACCEPT_SANDBOX` ниже) может сразу стоять `false` — на неё никто не
ходит, пока подписка не включена кюлл-свитчем. Остальные пункты — план на
момент 0.8.1:

- [ ] `APPLE_BUNDLE_ID` — дефолт `com.onezee.TripTrack`, менять не нужно.
- [ ] `APPLE_ENVIRONMENT=Production`.
- [ ] **`APPLE_APP_APPLE_ID`** — числовой Apple ID приложения (App Store
      Connect → App Information). **Обязателен для прода**: в `Production`
      библиотека Apple сверяет его в КАЖДОМ уведомлении, и без него они не
      пройдут проверку подписи (401, а не «тихо не обработалось»).
- [ ] `APPLE_ACCEPT_SANDBOX=false` на проде (включать временно только на
      время проверки песочницы через боевой URL, затем выключать обратно —
      см. §5 чек-листа `docs/plus.md`).
- [ ] `APPLE_ISSUER_ID` / `APPLE_KEY_ID` / `APPLE_PRIVATE_KEY` — только если
      заводили ключ из §2 (`.p8` в base64, тот же приём, что у
      `DB_CERT_BASE64`).
- [ ] Все пять — **не строгие**: пустое значение пишет предупреждение в лог
      на старте, а не роняет API (прецедент `SecretsConfig`).

- [ ] Слить `release/0.8.0` в `master` и запушить — деплой идёт с `master`
      (`.gitlab-ci.yml` на каждый пуш).
- [ ] **Миграция `1792000000000-AddPlus` guarded**, прод живёт на
      `DB_SYNC=true` и создаёт то же самое из сущностей — миграция здесь

- [ ] Кнопка «Request a Test Notification» из §2 — если ещё не нажимали.

## 5. iOS — пальцем на устройстве (после деплоя бэкенда) [ОТЛОЖЕНО НА 0.8.1]

**Не нужно для сабмита 0.8.0** — все пункты ниже про подписку, донат и
ручную поездку, которые сейчас скрыты кюлл-свитчем и никому не показываются.
Раздел остаётся планом на момент включения фичи.

Автотесты закрывают гейт, резолверы косметики и арифметику расстояния.
Ниже — то, что видит только человек, и то, что нельзя проверить в
симуляторе (StoreKit Testing симулирует покупку, но НЕ настоящую песочницу
Apple).

- [ ] **Sandbox-покупка на устройстве.** Sandbox Tester в Settings → App
      Store → Sandbox Account (создать заранее в Users and Access → Sandbox
      Testers). Открыть пейвол (Профиль → «Плюс» или любой замок косметики),
      купить годовую подписку с пробным периодом — подтвердить паролем
      sandbox-аккаунта, пейвол закрывается, замки снимаются СРАЗУ.
- [ ] **`/plus/attach` дошёл.** После покупки — `POST /plus/status` (или
      просто перезапуск приложения) должен вернуть активную подписку;
      смотреть `plus_subscription` в базе — строка появилась с правильным
      `product_id`/`environment=Sandbox`.
- [ ] **«Восстановить покупки».** Удалить и переустановить приложение (или
      второе устройство с тем же sandbox-аккаунтом) → пейвол → «Восстановить
      покупки» → «Плюс» вернулся без нового списания.
- [ ] **Отмена → грейс.** Profile → активная строка подписки → «Управлять
      подпиской» (системный лист Apple) → отменить. Доступ остаётся до конца
      уже оплаченного периода (грейс/обслуживание до `expires_at`) — это
      ожидаемо, не баг. В sandbox период укорочен Apple самостоятельно (около
      нескольких минут вместо года/месяца) — не наша настройка.
- [ ] **Донат.** Профиль → «Поддержать» → любая сумма → тост «спасибо» и
      больше ничего не меняется на экране; сервер про покупку не узнаёт.
- [ ] **Витрина РФ.** Sandbox-аккаунт с регионом RU (или смена Storefront
      теста) → «Плюс» и все премиум-пункты исчезают из профиля и настроек
      целиком, а не показываются с замком. Уже купленный на другой витрине
      «Плюс» продолжает работать.
- [ ] **Косметика на чужом профиле/гараже.** Купить «Плюс» → выбрать
      премиум-фон/рамку/фон карточки машины/цвет линии → открыть свой профиль
      С ДРУГОГО аккаунта (или через `/auth/me` для контроля) — видно то же,
      что выбрано. Отписаться (истечь в sandbox) → косметика гаснет на
      публичной стороне, но выбор остаётся в базе.
- [ ] **Ручная поездка.** Профиль → «Мои» → «+» (или «…» в шапке ленты) →
      только с активным «Плюсом» → маршрут по адресам, до 3 промежуточных
      точек, машина, дата → «Создать». Карточка с карандашом «вписана
      рукой», без графика скорости; одометр машины и «Атлас» сдвинулись
      сразу, опыт и уровень — нет.
- [ ] **Условия и приватность в пейволе** — обе ссылки открываются, «Плюс»
      явно называет цену и период ДО оплаты (виден на самом пейволе, не
      только в системном листе), подпись автопродления на месте на всех
      тринадцати языках.

## 6. Сабмит

1. **Версию НЕ поднимать заново** — `project.yml` уже `MARKETING_VERSION:
   "0.8.0"`, `CURRENT_PROJECT_VERSION: "62"` во всех трёх блоках; запустить
   `xcodegen generate`.
2. **`.xccurrentversion` = `TripTrack v19`.** Одна новая версия модели —
   `xcodegen generate` **ДВАЖДЫ** (первый прогон переписывает файл на
   прежнюю версию), проверить после генерации.
3. **Sentry**: ключа `SENTRY_DSN` в шаблоне `TripTrack/Info.plist` НЕ БЫЛО
   ни разу за всю историю файла — оттого Sentry молчал десять релизов, хотя
   `Local.xcconfig`, `AppConfig.sentryDSN` и вызов `SentryService.start()`
   были на месте. Строка добавлена в 0.8.0; проверить, что
   `SENTRY_DSN[config=Release]` в `Local.xcconfig` на месте, и после архива —
   `/usr/libexec/PlistBuddy -c "Print :SENTRY_DSN"
   <архив>/…/TripTrack.app/Info.plist` не пуст. В прогоне тестов то же самое
   держит `SentryDSNWiringTests` по собранному Debug-продукту.
4. Xcode → Product → Archive → Distribute → App Store Connect.
5. **[ОТЛОЖЕНО НА 0.8.1] «Товары из §1 уже «Ready to Submit» ДО этого шага».**
   Для 0.8.0 неактуально: в разделе In-App Purchase при сабмите выбирать
   нечего, товары не заводятся.
6. **«What's New» во все двенадцать локалей** карточки из `app-store.md` —
   не тринадцать языков приложения. Слот «Finnish» держит ФИЛИППИНСКИЙ
   текст, казахского в карточке нет вовсе. Тексты уже без «Плюса», доната и
   ручной поездки — см. `app-store.md`.
7. **[ОТЛОЖЕНО НА 0.8.1] App Privacy — обновить, не пропустить.** Для
   0.8.0 неактуально: без товаров в билде покупок не бывает, анкета
   остаётся такой же, как в 0.6.8 и 0.7.0 (Purchase History НЕ добавляется
   в этот сабмит). Абзац ниже — план на момент включения кюлл-свитча: «В
   отличие от 0.6.8 и 0.7.0 в этом релизе ЕСТЬ изменение: «Purchases →
   Purchase History» переходит с ❌ на ✅ (App Functionality, Linked to You,
   Tracking = No) — сервер хранит статус подписки по аккаунту. Донат входит
   — это тоже покупка. Текст ответа — `app-review-notes.md`. Тем же ходом
   обновлены (проверить, что не разъехались): `docs/releases/app-privacy.md`
   строка 24 И ФАЙЛ `TripTrack/PrivacyInfo.xcprivacy` — блок
   `NSPrivacyCollectedDataTypePurchaseHistory`, `Linked = true`,
   `Tracking = false`, цель `AppFunctionality`. Манифест — не дубль анкеты:
   Xcode собирает из него Privacy Report, и расхождение видит МАШИНА.»
8. **Notes для ревьюера** — блок v0.8.0 из `docs/releases/app-review-notes.md`.
   Пункт **[ОТЛОЖЕНО НА 0.8.1]** «How to test the subscription in sandbox»
   (свой Sandbox Tester, не Sign in with Apple ревьюера — это разные учётки)
   в 0.8.0 не нужен — тестировать нечего.
9. **Дату в CHANGELOG**: `## [0.8.0] -- в ревью` → дата отправки.

## 8. Что осталось ЗА версией (решения, не долг)

- **Google Play, семейный доступ, промокоды, реферальные, серверные скидки,
  веб-подписка** — не в 0.8.0 (спека §6). Семейный доступ Apple даёт сам,
  своей реализации не требует.
- **Лимит машин и постеры отклонены владельцем**, не входили в обсуждение
  этой версии.
- **Аналитика воронки подписки — 0.9.0.**
- **Правка трека ручной поездки после создания не делается** — только
  «удалить и создать заново» (спека §6).
- **Большой аудит безопасности платежей** (идемпотентность, повторные
  вебхуки, гонки привязки) — отдельная задача плана, идёт/прошла после
  интеграции всех веток, независимо от этого документа.
