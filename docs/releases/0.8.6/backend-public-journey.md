# Открытие публичного путешествия

8 октября 2026 после выпуска 0.8.6 пользователь сообщил: ссылка
«Часть путешествия» в ленте открывает экран «Путешествие недоступно».
Гостевой запрос к production `POST /social/journey` воспроизвёл
`UNKNOWN_SERVER_ERROR`; серверный лог содержал TypeORM TypeError
`Cannot read properties of undefined (reading 'databaseName')`.

## Причина и исправление

`SocialService.loadLegs` сочетал JOIN автора, `take(500)` и сортировку
`t.start_date`. Для такой пагинации TypeORM разрешает сортировку через
метаданные entity, поэтому нужно свойство `t.startDate`. До обращения
к PostgreSQL построитель запроса падал. Тот же метод использует список
публичных путешествий профиля.

В backend commit `a5ad8d8` изменена сортировка. Условия приватности, даты,
исключённые поездки и лимит сохранены. Миграций нет. Правка отправлена в
`master`; в 17:08 МСК подтверждён обновлённый работающий контейнер с
исправленным кодом и статусом `healthy`.

## Проверки

- Новый тест с настоящими entity metadata и TypeORM query builder без
  подключения к БД воспроизводит исходный сбой для гостя и владельца.
  После правки он проходит; проверяет JOIN, DISTINCT, лимит и приватность.
- 130 тестов: social.service, journey-legs, journey-query — прошли.
- `tsc --noEmit --incremental false -p tsconfig.build.json` — прошёл.
- Production: публичное путешествие возвращает две публичные поездки для
  UUID в верхнем и нижнем регистре; публичный список профиля также успешен.

Авторизованный запрос владельца и интерфейс iPhone после деплоя отдельно
не проверялись. iOS-код и архив 0.8.6 (75) не менялись; новый билд для
этого исправления не нужен. Подробный локальный отчёт сохранён вне Git
в каталоге TripTrack-Reviews/2026-10-08-public-journey.
