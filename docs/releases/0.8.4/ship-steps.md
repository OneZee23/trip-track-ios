Состояние на 30 сентября 2026, сверено командами, а не по памяти:

- iOS: ветка `release/0.8.4`, версия **0.8.4 (67)**. Ветки `release/0.8.4` на
  `origin` **НЕТ вовсе** — первый пуш будет с `-u`.

  синхронны с `origin` (0 и 0 в обе стороны), теги `v0.8.0`…`v0.8.3` на

  `git merge-base --is-ancestor`.
- Бэкенд: `master`, рабочее дерево чистое, **незапушенного ничего**.
  Миграции 0.8.3 уже в проде. **В этом релизе бэкенд не трогаем вовсе.**
- Незакоммиченным в дереве остаётся работа по экрану автомобиля — она НЕ
  входит в этот сабмит, см. шаг 6.

## ШАГ 1. App Store Connect — ПЕРВЫМ, до кода

Это настоящий гейт релиза. Пока товаров нет, приложение честно не показывает
ничего платного, и переключать флаг бессмысленно: витрина откроется, а
покупать будет нечего.

Подробная инструкция с ценами — `app-store-connect-setup.md`. Порядок:
соглашение **Paid Apps** → группа подписок `pro` с двумя тарифами → три
Consumable для чаевых → сверка Product ID с кодом → «Ready to Submit».

**Product ID переименовать потом нельзя никогда** — только удалить и завести
новый. Сверить побуквенно:

```
com.onezee.TripTrack.pro.yearly
com.onezee.TripTrack.pro.monthly
com.onezee.TripTrack.tip.small
com.onezee.TripTrack.tip.medium
com.onezee.TripTrack.tip.large
```

## ШАГ 2. Переключить флаг и собрать

Только после того, как товары в «Ready to Submit».

```bash
cd ~/OneZeeProjects/trip-track
# PlusAvailability.isEnabled: false -> true
```

Вместе с флагом удаляется его сторож —
`PlusAvailabilityTests.testShippedBuildKeepsPlusHidden`. Он написан так,
чтобы упасть в день переключения; поправить его вместо удаления значит
оставить в наборе тест, который сторожит отменённое решение.

```bash
xcodegen generate
nice -n 10 caffeinate -dimsu xcodebuild test -scheme TripTrack \
  -configuration Debug -destination 'platform=iOS Simulator,name=iPhone 16' \
  -only-testing:TripTrackTests -jobs 8
```

Полный `xcodebuild test` без `-only-testing` вешается на UI-таргете — гонять
UI-туры по одному и только когда они нужны.

## ШАГ 3. Приёмка платного на устройстве

Единственное, что не проверяется ни симулятором, ни тестом: StoreKit Testing
врёт в двух местах (записано в доккомментариях тестов `PlusStore`), а
настоящее поведение видно только против живого App Store. Список — в
[checklist.md](checklist.md), раздел «Приёмка платного». Коротко: покупка,
сеть выключена, отмена, «ждём подтверждения», восстановление на чистом Apple
ID, истечение, чаевые, и отдельно — что на витрине РФ платного не видно
нигде.

## ШАГ 4. Пуш и тег

```bash
cd ~/OneZeeProjects/trip-track
git push -u origin release/0.8.4
git tag v0.8.4 && git push origin v0.8.4
```

Перед пушем — проверка на секреты, как всегда в публичной репе:

```bash
git grep -nE 'ssh [a-z]+@|[0-9]{1,3}(\.[0-9]{1,3}){3}|BEGIN [A-Z ]*PRIVATE KEY'
```

И помнить: `git push --mirror` в этой репе делать нельзя — он вытолкнет
служебные `refs/t3/`.

## ШАГ 6. Экран автомобиля — ПОСЛЕ, отдельно

Код экрана автомобиля лежит в ветке, но в этот сабмит не идёт: entitlement
`com.apple.developer.carplay-driving-task` выдаёт Apple по заявке, и до
выдачи Release-сборка с ним не подписывается. В Release его и нет — держит
`EntitlementsWiringTests`, в Debug он есть, чтобы можно было смотреть сцену
в симуляторе CarPlay.

Действие владельца: отправить Apple заявку на entitlement (форма CarPlay в
разделе разработчика, категория **driving task**). Ответ приходит неделями.
Как только выдан — CarPlay добавляется в Release-файл прав и уезжает
следующей версией, вместе со строкой в «What's New».
