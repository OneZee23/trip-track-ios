# App Store Connect — товары для 0.8.4

Это ЕДИНСТВЕННОЕ, что нельзя сделать из репозитория, и это самая длинная
часть по времени: соглашение о платных приложениях проходит проверку
банковских и налоговых данных, и она измеряется днями, а не минутами.
**Начинать с него, всё остальное — потом.**

## Шаг 0. Соглашение о платных приложениях

App Store Connect → **Business** (прежде «Agreements, Tax, and Banking») →
**Paid Apps**.

- [ ] Соглашение принято и в статусе **Active**.
- [ ] Банковские реквизиты заведены.
- [ ] Налоговые формы заполнены (для грузинского аккаунта это W-8BEN).

Пока здесь не «Active», **товары создать нельзя вовсе** — раздел покупок в
приложении просто не даст их завести. Это и есть вещь, которую надо проверить
первой.

## Шаг 1. Подписка — группа и два тарифа

App Store Connect → приложение → **Monetization → Subscriptions**.

**Группа подписок:** имя `pro`. Группа одна, и это важно: два тарифа в ОДНОЙ
группе — это одна подписка с выбором периода, и человек может перейти с
месяца на год без двойной оплаты. Две группы означали бы две разные подписки,
которые можно купить обе сразу.

| Product ID | Reference Name | Период | Цена | Вводное предложение |
|---|---|---|---|---|
| `com.onezee.TripTrack.pro.yearly` | PRO Yearly | 1 год | *решает владелец* | **7 дней бесплатно** |
| `com.onezee.TripTrack.pro.monthly` | PRO Monthly | 1 месяц | *решает владелец* | нет |

**Product ID переименовать потом НЕЛЬЗЯ НИКОГДА** — его можно только удалить
и создать заново, потеряв всю историю покупок. Скопировать строки из таблицы
буква в букву; ровно эти строки лежат в `PlusStore.yearlyID`/`monthlyID`.

Локализованные названия на каждый тариф (минимум английский, лучше все
двенадцать локалей карточки):

- год — «TripTrack PRO — yearly» / «TripTrack PRO — год»;
- месяц — «TripTrack PRO — monthly» / «TripTrack PRO — месяц».

- [ ] Группа `pro` создана.
- [ ] Два тарифа заведены с ТЕМИ ЖЕ Product ID.
- [ ] У годового включено вводное предложение: **Free trial, 1 week**.
      У месячного — НЕТ. Приложение читает это у Apple
      (`Product.SubscriptionInfo.isEligibleForIntroOffer`) и обещает неделю
      только тому, кому её реально дадут: обещать её вернувшемуся подписчику —
      это отказ ревью 3.1.2 и списание полной цены у человека, который ждал.
- [ ] Цены назначены во всех регионах (Apple предложит таблицу от базовой).
- [ ] Скриншот для ревью и описание подписки заполнены — без них тариф не
      уходит на рассмотрение.

## Шаг 2. Чаевые — три разовые покупки

**Monetization → In-App Purchases**, тип **Consumable** (не Non-Consumable:
человек может дать чаевые второй раз, и он должен мочь).

| Product ID | Reference Name | Смысл |
|---|---|---|
| `com.onezee.TripTrack.tip.small` | Tip Small | «Кофе автору» |
| `com.onezee.TripTrack.tip.medium` | Tip Medium | «Обед автору» |
| `com.onezee.TripTrack.tip.large` | Tip Large | «Бак бензина автору» |

Цены в `Config/TripTrack.storekit` стоят 0.99 / 2.99 / 9.99 — это числа для
локальных прогонов, а не решение. В ASC назначаются свои.

- [ ] Три покупки заведены, тип Consumable.
- [ ] Локализованные названия и описания.
- [ ] В описании прямо сказано, что взамен не даётся ничего: это требование
      Apple к чаевым и одновременно то, что отличает их от тарифа.

## Шаг 3. Сверка с кодом

После заведения — прогнать глазами:

- [ ] `PlusStore.yearlyID` == `com.onezee.TripTrack.pro.yearly`.
- [ ] `PlusStore.monthlyID` == `com.onezee.TripTrack.pro.monthly`.
- [ ] Идентификаторы чаевых в `Config/TripTrack.storekit` совпадают с ASC.
- [ ] `Config/TripTrack.storekit` — файл только для симулятора; на настоящем
      телефоне продукты приезжают из ASC, и расхождение между этими двумя
      списками видно ТОЛЬКО на устройстве.

## Шаг 4. Включение «Плюса» в коде — одна строка

`PlusAvailability.isEnabled` с `false` на `true`. Вместе с этим **удаляется**
`PlusAvailabilityTests.testShippedBuildKeepsPlusHidden`: он написан так, чтобы
упасть в день, когда флаг переключат, — и переключать его надо вместе с
удалением теста и решением, а не молча правя константу.

Это делается в коде и НЕ раньше, чем товары в ASC будут в статусе «Ready to
Submit»: приложение с включённым «Плюсом» и без товаров показывает пейвол без
единого тарифа.

## Что уже готово и трогать не надо

- **Бэкенд.** `PlusModule` в проде с 0.8.0: привязка покупки, счётчик,
  косметика в чужом профиле. Новых миграций 0.8.4 не требует.
- **Витрина РФ.** `PlusGate` отдаёт `.hidden` на `Storefront.current
  .countryCode == "RUS"` — ни пейвола, ни замков, ни чаевых. Проверять это на
  симуляторе нечем; на устройстве — только сменой региона Apple ID.
- **Очередь привязки покупки** (`PlusAttachQueue`) и хранение подписи Apple в
  Keychain (`PlusJWSVault`).
