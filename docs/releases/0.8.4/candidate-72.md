# 0.8.4 (72) — проверка записи после дорожного теста

Кандидат подготовлен 5 октября 2026. Release-архив проверен; Apple приняла
загрузку в 10:36 МСК и завершила обработку. Сборка доступна внутренней группе
OneZee Group (3 тестировщика), статус в TestFlight — Ready to Submit.
Build ID: `4ca75cd5-9a8c-493f-a311-3c0b0be401dc`. Заметки What to Test добавлены.
72 на App Review не отправлялся и публично не выпускался.
Apple одобрила 0.8.4 (70), группу PRO, оба тарифа и три чаевых; версия
остаётся в Pending Developer Release. Ручной выпуск не выполнялся.

В кандидат входят изменения [71](candidate-71.md), включая исправление
первого открытия деталки от 3 октября, и следующие исправления записи.

## Что исправлено

- Прогноз позиции для экрана больше не меняет состояние GPS-фильтра.
  Частота обновления интерфейса не должна менять записанный маршрут.
- После разрыва сигнала дольше десяти секунд фильтр начинает оценку заново,
  не переносит старую скорость через несколько минут без измерений.
- Неизвестная скорость сохраняется как неизвестная при передаче данных
  провайдера. Валидная скорость без курса остаётся валидной.
- Проверка последовательности сырых координат отклоняет невозможные скачки
  до фильтра. Отклонённая точка не меняет опорную позицию. Повтор одной
  координаты десятки раз за долю секунды не усиливает уверенность фильтра.
- Сохранённый трек, живая линия и открытие территории получают прошедшие
  проверку точки. Сам индикатор текущего GPS продолжает читать провайдер.
- Невозможная скорость не становится рекордом. При редких нормальных
  измерениях правдоподобное перемещение за время разрыва задаёт нижнюю
  границу максимальной скорости; известная нулевая скорость в конечной
  точке остаётся нулевой. Такая поездка не удаляется как пешая, в том числе
  при восстановлении прерванной записи.
- Границы ручных пауз сохраняются сразу. Пересчёт расстояния, время движения,
  расстояние до отметки и достройка пропусков не пересекают эти границы.
  Обычный разрыв GPS по-прежнему может соединяться правдоподобным отрезком.
- Убраны повторяющиеся сообщения каждой отрисовки, вытеснявшие полезный
  журнал. Старт, пауза, продолжение, завершение и ошибки остаются в нём.

## Совместимость и границы проверки

Core Data v22 добавляет только optional `recordingBreaksJSON` на поездке.
Сервер получает optional `recordingBreaks`: отсутствие поля сохраняет
существующие границы, пустой массив явно очищает их. Обновление сервера
должно предшествовать выпуску клиента. Старые поездки без этих данных
не получают выдуманных пауз; их исходные точки автоматически не заменяются.

Плоские превью маршрута и атлас пока могут визуально соединять участки
до и после паузы. Эта работа разделяет расчёт и достройку, но не меняет
формат геометрии превью. Нельзя считать её полной поддержкой разрывов во
всех отображениях маршрута.

Старый клиент сохраняет незнакомые границы на сервере, но при повторной
обработке поездки может загрузить статистику, рассчитанную без них. Массовый
пересчёт при pull не выполняется: delta-ответ может не содержать полного трека.

Дорожный тест выполнялся одновременно в Dev 71 и TestFlight 70 на одном
iPhone, с ручным запуском. Разница пауз подтверждена журналом и владельцем.
Сырые данные повторно прогнаны локально; это проверяет обработку измерений,
но не доказывает фактический пробег через зону глушения. Контрольного
километража машины нет. Исходные контейнеры сохранены отдельно и не изменены.

## Проверки

- Первые проверки фильтра и записи: 93 теста прошли.
- Проверки с метаданными пауз: 143 теста прошли, включая миграцию v21 → v22,
  совместимость синхронизации, дистанцию, достройку и дорожный запрос,
  во время которого приходят новые границы пауз.
- Полный набор: 2 847 unit-тестов, 0 ошибок, iOS 18.6. Включает восстановление
  поездки с редкими измерениями, паузой и остановкой в конце.
- Сервер: 68 тестов в четырёх наборах, TypeScript и чистая сборка прошли.
  Ответ различает неизвестные границы (`null`) и явную очистку (`[]`).
- iOS 18.6: 7 UI-сценариев прошли — пауза/продолжение, защита от свайпов,
  завершение записи и повторное открытие деталки с полноэкранной картой.
- iOS 26.5: 59 профильных unit-тестов и 4 UI-сценария прошли, включая
  системные разрешения и завершение записи. После изоляции старой Core Data
  модели в тестовой фикстуре повторно прошли 20 тестов миграции/записи/пауз;
  предупреждения о конкурирующих моделях устранены без изменения приложения.
- Повторная обработка сырых дорожных измерений: 24 прогона. Проверены
  сохранённые паузы и отдельный сценарий без них; ложная конечная точка
  отклоняется, разница статистики до и после финализации не растёт на километры.
- Сервер обновлён штатным GitLab CI, commit `29e6528`. Проверены новый image,
  healthy, nullable JSONB-колонка и оба сериализатора в работающем контейнере
  на синтетических данных. Личные поездки не менялись. Старый image сохранён;
  откат подготовлен с `DB_SYNC=false`, чтобы не удалить новую колонку.
- Архив 72: Release, production API, подпись, версии приложения и расширений,
  Core Data v22 с v21 для миграции, совпадение UUID бинарника/dSYM проверены.
  StoreKit test config и тестовые bundles в архив не включены; хеши 1 003
  исходных файлов совпадают с зафиксированными перед архивированием.

  предупреждение об отсутствующем dSYM стороннего `Sentry.framework`;
  dSYM самого TripTrack присутствует и соответствует бинарнику. Повторный
  билд ради этого предупреждения не загружался. Предыдущие архивы 71
